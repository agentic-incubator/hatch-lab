# Pilot Planner Skill

This skill helps you design and execute pilot programs that validate product-market fit while minimizing risk and maximizing
learning velocity. Using lean startup principles, we'll create MVPs that test critical assumptions.

## Core Capabilities

I can help you:

- Define Minimum Viable Products (MVPs)
- Structure pilot programs for maximum learning
- Establish clear success/failure criteria
- Design rollout and scaling strategies
- Create measurement frameworks
- Manage stakeholder expectations
- Plan resource allocation

## Pilot Planning Framework

### Step 1: MVP Definition

#### MVP Scoping Matrix

```
MUST HAVE          SHOULD HAVE
(Core Value)       (Enhancers)
    │                  │
    ▼                  ▼
┌──────────┐      ┌──────────┐
│ Feature  │      │ Feature  │
│ Feature  │      │ Feature  │
└──────────┘      └──────────┘
    │                  │
    ▼                  ▼
COULD HAVE         WON'T HAVE
(Nice to Have)     (Future)
┌──────────┐      ┌──────────┐
│ Feature  │      │ Feature  │
│ Feature  │      │ Feature  │
└──────────┘      └──────────┘
```

#### Types of MVPs

**Low-Fidelity MVPs** (Week 1-2)

- **Concierge MVP**: Manual service delivery
- **Wizard of Oz**: Simulated automation
- **Landing Page**: Value prop testing

**Medium-Fidelity MVPs** (Week 3-8)

- **Prototype**: Interactive mockup
- **Single Feature**: Core functionality only
- **Crowdfunding**: Pre-order validation

**High-Fidelity MVPs** (Week 9-16)

- **Limited Release**: Regional/segment launch
- **Beta Program**: Early adopter testing
- **Pilot Implementation**: Full solution, small scale

### Step 2: Hypothesis Formulation

#### Hypothesis Template

```
We believe [TARGET CUSTOMER]
Will [BEHAVIOR/ACTION]
Because [MOTIVATION/NEED]
We'll know this is true when [METRIC] reaches [TARGET]
```

#### Critical Assumptions to Test

**Desirability Assumptions**

- Problem exists and is painful
- Solution addresses the problem
- Customers will adopt solution
- Value exceeds alternatives

**Feasibility Assumptions**

- Technical solution works
- Can deliver at required quality
- Can scale to meet demand
- Team can execute

**Viability Assumptions**

- Customers will pay
- Unit economics work
- Can acquire customers profitably
- Business model sustainable

### Step 4: Measurement Framework

#### North Star Metric Selection

```
ENGAGEMENT         GROWTH           REVENUE
Daily Active      User Referrals   MRR/ARR
Time in App       Viral Coeff.     ARPU
Feature Usage     Sign-up Rate      Conversion
```

#### Pirate Metrics (AARRR)

```
Acquisition → Activation → Retention → Revenue → Referral
     ↓            ↓            ↓          ↓         ↓
How users    First value   Come back    Pay      Tell others
find you     experience
```

#### Leading vs Lagging Indicators

**Leading** (Predictive):

- Sign-ups per day
- Feature adoption rate
- Session duration
- Support ticket volume

**Lagging** (Results):

- Monthly revenue
- Churn rate
- Customer satisfaction
- Market share

### Step 5: Risk Mitigation

#### Risk Assessment Matrix

```
        Low Impact    High Impact
High    ┌─────────┬──────────┐
Prob.   │ Monitor │ Critical │
        ├─────────┼──────────┤
Low     │ Accept  │ Mitigate │
Prob.   └─────────┴──────────┘
```

#### Common Pilot Risks

1. **Selection Bias**: Non-representative participants
2. **Honeymoon Effect**: Initial enthusiasm wanes
3. **Support Inflation**: Unsustainable hand-holding
4. **Feature Creep**: Scope expansion
5. **Premature Scaling**: Growing before validation

## Advanced Pilot Techniques

### Cohort-Based Pilots

```
Cohort 1 → Learn → Improve → Cohort 2 → Learn → Scale
```

Benefits:

- Iterative improvement
- Reduced risk
- Better support quality
- Clear comparison

### A/B Testing Framework

```
Control Group     vs    Treatment Group
(Current State)         (New Solution)
      ↓                       ↓
   Measure              Measure
      └─────────┬─────────┘
           Statistical
           Significance
```

### Innovation Accounting

Track validated learning through:

- Hypothesis → Experiment → Data → Insights
- Build → Measure → Learn loops
- Pivot or Persevere decisions

## Example Pilot Plan

**Product**: AI-Powered Sales Coaching Platform

**Pilot Design**:

```markdown
### MVP Scope

- Core: Real-time call analysis
- Included: Basic coaching tips
- Excluded: CRM integration, reporting

### Pilot Parameters

- Duration: 8 weeks
- Participants: 20 sales reps (2 teams)
- Company Size: Mid-market B2B SaaS

### Success Criteria

PRIMARY: 20% improvement in close rate
SECONDARY:

- 80% daily usage
- NPS > 50
- 15% reduction in ramp time

### Timeline

Weeks 1-2: Setup & training
Weeks 3-8: Active pilot
Week 9: Analysis & decision

### Measurement Plan

- Daily: Usage metrics
- Weekly: Performance metrics
- Bi-weekly: User interviews
- End: Comprehensive analysis
```

## Go/No-Go Decision Framework

### Green Light (Proceed to Scale)

✅ Primary metric exceeded
✅ Positive unit economics
✅ Strong user feedback
✅ Technical stability
✅ Clear path to scale

### Yellow Light (Iterate)

⚠️ Mixed results
⚠️ Need specific improvements
⚠️ Additional testing required
⚠️ Pivot opportunity identified

### Red Light (Stop/Pivot)

❌ Primary metric not met
❌ Fundamental assumption wrong
❌ No path to profitability
❌ Better opportunity identified
