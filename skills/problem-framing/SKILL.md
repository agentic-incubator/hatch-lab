# Problem Framing Skill

This skill helps you properly define and frame problems before attempting to solve them. Using structured methodologies,
we'll ensure you're addressing root causes, not just symptoms, and solving the right problem.

## Core Capabilities

I can help you:

- Define problems clearly and precisely
- Identify root causes vs symptoms
- Apply systems thinking to complex problems
- Frame problems from multiple perspectives
- Prioritize problems worth solving
- Avoid solution bias in problem definition
- Create problem statements that drive action
- Validate problem assumptions

## Problem Framing Framework

### Step 1: Problem Identification

#### Problem Discovery Methods

```
OBSERVATION
├─ Ethnographic study
├─ Process observation

DATA ANALYSIS

├─ Survey results
└─ Support tickets

SYSTEM ANALYSIS
├─ Bottleneck identification
├─ Failure point analysis
├─ Inefficiency mapping

#### Problem vs Symptom Distinction

```
SYMPTOM → PROBLEM → ROOT CAUSE
   ↓         ↓           ↓
Observable  Underlying   Origin
Effect      Issue        Source

Example:
Low sales → Poor conversion → Unclear value prop
(symptom)   (problem)        (root cause)
```

### Step 2: Problem Analysis

#### Five Whys Technique

```
Problem: Users abandoning signup
↓
Why? → Form takes too long
↓
Why? → Too many required fields
↓
Why? → Collecting unnecessary data
↓
Why? → No clear data strategy
↓
Why? → Lack of user research
↓
ROOT CAUSE: Insufficient user understanding
```

### Step 3: Problem Framing

#### Problem Statement Templates

**Basic Template**:

```
The problem is [description]
affecting [stakeholders]
resulting in [impact/consequences]
```

**How Might We (HMW) Format**:

```
How might we [action]
for [user]
so that [outcome]
while [constraint]?
```

**Problem-Opportunity Statement**:

```
Currently [situation]
which causes [negative impact]
If solved, would result in [positive outcome]
Success looks like [measurable criteria]
```

#### Reframing Techniques

**Perspective Shifting**:

```
ORGANIZATIONAL VIEW
"We're losing money"
↓
CUSTOMER VIEW
"I can't achieve my goals"
↓
SYSTEM VIEW
"Value isn't flowing efficiently"
```

**Abstraction Ladder**:

```
MORE ABSTRACT
↑
"Improve quality of life"
"Enhance mobility"
"Provide transportation"
"Build better cars"
"Fix engine problems"
↓
MORE CONCRETE
```

**Constraint Removal**:

```
Original: "How do we fit more in the warehouse?"
Reframed: "How do we reduce inventory needs?"
```

```

        (1-10)    (1-10)      (1-10)

Problem B: 10 × 5 × 3 = 150

## Example Problem Framing

**Context**: E-commerce Platform

```markdown
### Initial Symptom

"Our conversion rate is declining"

### Five Whys Analysis

1. Why? → Cart abandonment increased 30%
2. Why? → Checkout process confuses users
3. Why? → Multiple unexpected fees appear
4. Why? → Pricing transparency not prioritized
5. Why? → Misalignment on customer trust importance

### Root Cause

Organizational focus on revenue optimization over customer trust

### Reframed Problem Statement

"How might we build customer trust through pricing transparency while maintaining healthy margins?"

### Validation Evidence

- 67% cite "unexpected costs" as abandonment reason
- Competitors with transparent pricing show 25% better conversion
- $2.3M annual revenue lost to abandonment

### Priority Score

Impact: 9 | Confidence: 8 | Ease: 6 | Total: 432
```

## Problem Framing Principles

### Good Problem Framing

✓ **Human-Centered**: Focuses on real people
✓ **Specific**: Clear boundaries
✓ **Measurable**: Success can be defined
✓ **Actionable**: Points toward solutions
✓ **Valuable**: Worth solving

### Poor Problem Framing

✗ **Solution Disguised**: "We need an app"
✗ **Too Broad**: "Improve everything"
✗ **Too Narrow**: "Change button color"
✗ **Blame-Focused**: "Users are stupid"
✗ **Impossible**: "Eliminate all errors"

## Questions I'll Ask You

To frame your problem:

- What triggered awareness of this problem?
- Who is affected and how?
- What evidence do you have?
- What's the impact if unsolved?
- What assumptions are you making?
- What constraints exist?
- How would you know it's solved?

## Common Framing Mistakes

⚠️ **Solution Jump**: Defining problem as lack of solution
⚠️ **Symptom Focus**: Addressing effects not causes
⚠️ **Single Perspective**: Missing stakeholder views
⚠️ **Assumption Based**: No evidence validation
⚠️ **Over-Constraining**: Artificial limitations
